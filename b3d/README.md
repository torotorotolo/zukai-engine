# b3d/ — 3DCG を焼く側

本編（226カット・34分04秒）のうち **66カット・9分43秒を3DCGに差し替える**ための一式。
選定表は Vault の `事故検証-3D差し替えカット選定-20260801`。
全体設計は Vault の `事故検証-3DCG完全自動パイプライン-設計-20260731`。

---

## 0. 絶対ルール

1. 🔴 **ローカルPCで Blender を動かさない。** メモリ4GB。Blender も `bpy` も入れない。
   ここに置くのは「命令書としての Python」だけで、実際に焼くのは Modal のGPUコンテナ。
2. 🔴 **`b3d/` は `tools/` を import しない。`tools/` は `bpy` を import しない。**
   つなぐのは JSON だけ（`b3d/shots.json` と `{cid}.anchors.json`）。
   この壁があるおかげで、4GB機で bpy が走らないことが構造で保証される。
   レンダ先を Modal から他所へ移すときも、書き直すのは `app_modal.py` だけで済む。
3. 🔴 **本編レンダを GitHub Actions に載せない。**
   GitHub の規約は GitHub-hosted runner を「そのリポジトリのソフトウェアプロジェクトの
   production / testing / deployment / publication」に限っている。動画の製造はここに入らない。
   Actions に残すのは検査（`check_*`）と軽量なQA画像だけ。
4. **アニメーションの時刻は正規化時間（0.0〜1.0）で書く。秒を書かない。**
   ナレーションを1行直しても3Dの記述は無傷で、尺だけが伸縮するようにするため。
5. **文字を3Dに入れない。** 日本語・寸法線・矢印は2D側（`tools/`）が乗せる。
   `fonts/` は woff2 で Blender は読めないし、既存の `fontmetrics.py` と
   `check_layout.py`（字幅の実測と机上検算）の資産をそのまま生かせる。
6. **物理シミュレーションを使わない。** 圧壊は Shape Key で潰す。
   参照ch（ジコビジュ）も物理を1カットも使っていない。逐次依存が消えて並列レンダが安全になる。
7. **乱数は必ず seed 固定。** 同じ発注書から同じ絵が出ないと、5巡のQCが成立しない。

## 2. 最初にやること

```bash
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 modal run b3d/app_modal.py
```

**費用は $0.05 未満。所要は数分。**

⚠️ **`PYTHONIOENCODING=utf-8` を必ず付ける。** 付けないと Modal CLI が出す `✓` を
Windows の cp932（日本語 Shift-JIS）が扱えず、`'cp932' codec can't encode character '✓'`
で **GPUに到達する前に落ちる**。2026-08-01 に実際に1回無駄にした。

これで次の2つが確定する。

1. **EEVEE Next がコンテナのGPUで本当に動くか**
2. **1コマ何秒か** ← 費用と所要時間の全数字がこの1個に乗っている

### 🔴 実測で確定した設定（2026-08-01）

| 項目 | 決定 |
|---|---|
| エンジン | **Cycles + OptiX**（EEVEE は Modal では動かない） |
| GPU | **L4**（$0.80/時） |
| サンプル数 | **32** |
| デノイズ | **OpenImageDenoise を GPU で**（`denoising_use_gpu = True`）★最重要 |
| 1コマ | **1.89秒**（1920×1080・体積フォグあり） |
| 本編3D 8,742コマ | **$3.67 ≒ ¥587** |

#### 1) EEVEE は使えない

| エンジン | 1コマ | 判定 |
|---|---|---|
| EEVEE Next | **24.52秒** | ❌ **GPUを掴めていない**。`EGL_BAD_MATCH` ×3・ソフト描画 |
| **Cycles + OptiX** | 5.98秒（T4） | ✅ `devices=['Tesla T4(CUDA)', 'Tesla T4(OPTIX)']` |

理由は構造的なもの。Modal のコンテナには**計算用の CUDA は渡るが、描画用の EGL/GLX は渡らない**。
`NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics` を指定しても `graphics` は効かなかった。
EEVEE は描画API（OpenGL/EGL）を使うので動かず、Cycles は計算API（CUDA/OptiX）を使うので動く。

⚠️ **EEVEE を使いたければ実VMを借りる基盤（Vast.ai / RunPod）に移すこと。**
そちらは本物のドライバが入っているので EEVEE が動く。ただし Cycles で足りるなら移す必要はない。

#### 2) 🔴 デノイズは必ず GPU で回す（いちばん効く一手）

Blender の既定デノイザ OpenImageDenoise は **既定で CPU 実行**。
L4 コンテナの CPU は数コアしかないので、そこが律速になる。

| L4 / 1920px / 32サンプル | 1コマ | 本編3D |
|---|---|---|
| デノイズ **CPU**（既定のまま） | 4.85秒 | ¥1,507 |
| **デノイズ GPU** ★ | **1.89秒** | **¥587** |
| デノイズ無し（参考） | 1.65秒 | ¥511 |

**デノイズ単体で CPU 3.2秒 → GPU 0.24秒（13倍）。品質は同一**（同じ OIDN を場所だけ変えている）。
`scene.cycles.denoising_use_gpu = True` の1行。これを忘れると費用が2.6倍になる。
OptiX 専用デノイザ（`denoiser='OPTIX'`）は失敗した。OIDN の GPU 実行のほうが品質も上なので追わない。

#### 3) サンプル数を落としても安くならない

同一 T4 での連続測定。1 → 32 で **26%しか増えない**（4.75 → 6.00秒）。
時間を決めているのはサンプル数ではなく固定費なので、**32を既定にしてよい**。
64以上は急に重くなる（8.94秒）ので上げない。

#### 4) GPU は L4

| GPU | $/時 | 秒/コマ | 本編3D |
|---|---|---|---|
| T4 | 0.59 | 7.41 | ¥1,697 |
| **L4** | 0.80 | **4.61** | **¥1,431** |
| A10G | 1.10 | 5.25 | ¥2,245 |

※この表はデノイズCPUのまま測ったもの。費用差は誤差（後述）に埋もれるが、
L4 は 1.4倍速く、測定のばらつきも小さいので L4 を既定にする。

#### 5) 解像度は素直に効く（デノイズGPU・L4）

| 解像度 | 1コマ | 本編3D |
|---|---|---|
| 1920px | 1.89秒 | ¥587 |
| 1280px | 1.08秒 | ¥336 |
| 960px | 0.82秒 | ¥255 |
| 640px | 0.62秒 | ¥192 |

→ **枠の中に貼るカットをフルHDで焼かないこと。** `shots.json` の `box` から
レンダ解像度を決める（16:9で焼いて縦長の枠に貼ると左右45%を捨てることにもなる）。

#### ⚠️ 測定の作法（ここを外すと嘘の表が出る）

- **比較は必ず1つのコンテナの中で連続実行する。** `remote()` を回数ぶん呼ぶと
  そのたび別の物理GPUが立ち、機体差（実測 ±20%）が効果の差より大きく出る。
  実際に「8サンプルが32サンプルより遅い」という表が出た。
- **1コマ目は捨てる。** カーネル読み込みで2〜3秒余計にかかる。
- T4 は同条件で 5.95 / 6.00 / 7.41 秒とばらついた。**費用の数字は ±20% で読む。**

### 🔴 検査が素通りした話（作り方を間違えた）

用意していた `assert_not_software()` は **1件も検出できなかった**。

```
[gpu] {'error': 'SystemError: GPU functions for drawing are not available in background mode'}
```

Blender は `-b`（画面なし）で動かすと GPU情報を取るAPI自体を封じる。
レンダラ名が取れないので `llvmpipe` 判定ができず、ガードは「判定できない＝合格」と扱った。
**「名前を見て判定する」設計が間違いだった。**

→ 正しい判定はこの3つ。いずれも background でも取れる。

1. `p.get_devices()` の戻りに実デバイスが居るか（Cycles は background でも取れる）
2. **stderr の `EGL Error` の件数**（`smoke()` が数えて `egl_errors` に入れている）
3. **1コマの実測秒**（軽いシーンで数秒を超えたらGPUではない）

### 🔴 なぜこれを最初にやるのか

EEVEE は GPU でしか動かない（Blender公式が明言している）。
そして GPU を掴み損ねると、Mesa の llvmpipe（CPUでGPUを真似るソフト描画）に
**エラーを出さずに落ちる**。そのまま描き切ってしまうので気づけず、
1コマ 30〜120秒（想定の25〜90倍）になって、無料枠 $30 を成果ゼロで焼き切る。

対策は3段で入れてある。

1. `app_modal.py` の apt に **Mesa のソフト描画ドライバを入れない**（落ちる先を物理的に無くす）
2. `NVIDIA_DRIVER_CAPABILITIES` に `graphics` を入れる
   （これが無いとコンテナには CUDA のライブラリしか渡らず、OpenGL/EGL が見えない）
3. `smoke.py` の `assert_not_software()` が実物のレンダラ名を見て、
   `llvmpipe` / `lavapipe` などが混ざっていたら **課金前に SystemExit する**

## 5. 潜水艇モデル — 8巡した記録（2026-08-01）

`builders/sub_titan.py`。**この1モデルで約35カットを撮る**ので、ここで形を固めた。
1巡＝4枚・約¥5・約2分。累計 $0.51（無料枠 $30/月 の 1.7%）。

### 到達点

| カット | 状態 | 使うカット |
|---|---|---|
| `hull_layers` 層の断面 | ✅ 5層・接着面4本・剥離層の朱赤と隙間が一目で読める | c414 / c416 / c428 / c431 |
| `hull` 耐圧殻 | ✅ チタンドーム・継ぎ目リング・ボルト18本・のぞき窓 | c204 / c205 / c417 |
| `exterior` 外観 | ✅ 潜水艇として読める。受け台・スラスター・黒ドーム | c107 / c203 / c403 / pr01 |
| `cutaway` 半割り | ✅ 5人が座る狭さが伝わる | c107 / c204 / c308 |

### 🔴 効いた判断は2つだけ

**① 「切ってから見せる」をやめた（5巡目）**
4巡かけて層の断面は一度も読めなかった。穴埋め（holes_fill）が不正な面を作り、
実寸の壁（直径1,674mmに対し127mm＝7.6%）はそもそも細すぎた。
→ `L.solid_arc()` で**最初から欲しい形だけを中実に作る**。
　 断面は「切った跡」ではなく最初から在る面になるので、必ず正しく出る。

**② カメラ距離を手で置くのをやめた（3〜4巡目）**
突き抜けも余白過多も、私が数字を手書きしたのが原因だった。
→ `L.camera(fill=0.8)` が対象の**投影サイズ**から距離を逆算する。
　 ⚠️ 外接球で決めてはいけない。細長い物体は左右に巨大な余白ができる。
　 既存の `check_layout.py`（字幅をフォントから実測）と同じ作法。

### 潰した欠陥の一覧（同じ踏み方をしないため）

| # | 症状 | 原因 |
|---|---|---|
| 1 | 円錐が逆向きに開く | `primitive_cone_add` の `radius1` は −Z 側。Y軸へ回すと +Y 側に来る → `L.taper()` |
| 2 | 受け台が浮いて「はしご」に見える | 脚の長さを胴体表面の高さから逆算していなかった |
| 3 | 層が1枚も見えない | **入れ子の筒は外から1枚しか見えない** |
| 4 | 断面が切れない | 法線をローカル空間へ変換していなかった |
| 5 | 断面に三角形のゴミ | `holes_fill` が不正な面を作る → `fill=False` を既定に |
| 6 | チタンが真っ黒 | `metal=1.0` は映り込む環境が要る → 0.35 へ |
| 7 | ハイライトが白飛び | 小さい強いスポット → 大きい弱い面光源 |
| 8 | カメラが対象を突き抜ける | `distance` を手書きしていた |
| 9 | 対象が画面の1/3 | 外接球で距離を出していた |
| 10 | 背景が暗い一色 | ワールドの Generated は **−1〜+1**。0〜1 と思い込んでいた |
| 11 | 断面の中が真っ黒 | 内部光が無い。炭素繊維は暗いので沈む |
| 12 | 人が「立って」見える | 足を前へ投げ出す／胴を倒す／頭を天井に近づける、の3つが要る |
| 13 | 人の胴体に黒い点 | `inside_light` を重心＝人の体内に置いていた → `offset` 必須に |
