# フリー素材の共通の棚 `ref/stock/` の設計

> **設計だけ**（このチャットでは棚を作らない）。棚を作るのは 19本目の ⑤b-1（素材の取得と同じチャット）。決まり＝ルール統合版 §2-5c（テーマに関連したフリー素材の映像は可・「イメージ」と出す・20%に数えない・AI 生成は使わない）。手本＝18本目の `ref/ep18/stock.json`（11本・回の中だけの台帳）。

## 1. なぜ共通の棚にするか
- 18本目は回の中だけの台帳だった＝次の回で同じ素材を使うとき、**探す・権利の頁を読む・字と顔を焼いて確かめる**をやり直すことになる
- 事故検証ch は海・夜・コンクリート・書類・工事など、回をまたいで同じ型の「イメージ」が要る＝確かめた区間を貯めれば ⑤b-1 の往復が減る
- 権利の記録（許諾の名・頁・作者・AI の印・取得日）を1か所にまとめる＝申し立てが来たとき、どの回のどのカットかがすぐ分かる

## 2. 置き方
```
ref/stock/
  stock.json        ← 台帳（git に入れる＝`git add -f ref/stock/stock.json` と名指し）
  media/            ← 動画そのもの（git に入れない）
    px_15204737.mp4
    pb_52888.mp4
  stills/           ← 確かめた区間の控えのコマ（git に入れない・検品の手元用）
```
- 🔴 **動画も控えの静止画も git に入れない**。Pexels License は「ほかの素材サイトで配る・手を加えずに売る」を、Pixabay Content License は「手を加えずに単独で配る（Standalone）」を禁じる。公開リポに素材そのものを置く＝配る、になりうる
- `.gitignore` の `ref/*` で棚は最初から外れている。入れてよいのは台帳1枚だけ＝**commit は `stock.json` の名指しだけ**（`git add -f ref/stock` のようにフォルダごと足さない）。push の前に `git diff --cached --name-only | grep '^ref/stock/' | grep -v 'stock.json$'` が空であることを確かめる
- 焼くとき（Actions）は台帳の `media`（サイトの動画ファイルの URL）から落として md5 で照らす＝`footage.fetch` と同じ道（18本目の clips.json の `media` と同じ）。控えのコマも落としたあとに作る
- 🔴 18本目は控えの静止画 11枚（`ref/ep18/stock/fb_c*.jpg`・うち Pixabay 2枚＝c114・c805）が公開リポに入っている＝**決め⑨（2026-10-06 カズヤくん）＝⑤b-1 で `git rm --cached` で git の管理から外す**（手元のファイルは残す・過去の履歴には残る・公開ずみの動画は直さない）。commit は名指し・出ていく commit を push の前に確かめる

## 3. 名前の付け方
- 鍵＝**`px_<Pexels の番号>`／`pb_<Pixabay の番号>`**（サイトの番号は変わらない・2つのサイトで番号がぶつからない・中身の言葉は鍵に入れない＝言葉は回ごとに変わる）
- ファイル＝`media/<鍵>.mp4`。どの版（幅）を落としたかは台帳の `rendition` に
- 回の側の `ref/epNN/clips.json` の鍵も**同じ鍵**にする（回ごとに別の名を付けない＝棚と回の対応を機械で引ける）
- 18本目の11本（`docs_binders_7710340` ほか）は、⑤b-1 で棚へ移すときに `px_7710340` の形に直して `used_in` に 18本目のカットを書く（`ref/ep18/` の中身は書き換えない）

## 4. 台帳 `stock.json` の欄（1本＝1つの鍵）
| 欄 | 中身 | 例・決まり |
|---|---|---|
| `site`・`page` | サイトの名と素材の頁 | Pexels・`https://www.pexels.com/video/…-15204737/` |
| `media`・`rendition`・`md5`・`size` | 落とした動画ファイルの URL・版・照合の値 | 幅1920以上の版。md5 は2回取って同じこと（落としかけを測らない） |
| `w`・`h`・`fps`・`sec` | 実測（ffprobe） | — |
| `title`・`author`・`posted` | 頁の題・作者・投稿日 | 投稿日は撮影日ではない（時代の判断に使わない） |
| `license`・`license_url`・`license_checked` | 許諾の名・頁・確かめた日 | 頁の JSON-LD の license を読んだ日 |
| `ai` | AI 生成の印 | Pexels＝頁の記載なし／Pixabay＝頁のデータ `isAiGenerated=false`。true は使わない |
| `what`・`place`・`era_note` | 写っているもの・撮影地・時代と型の注意 | 例「事故の後の撮影＝周辺の空撮なら跡地が写る恐れ」 |
| `ok_ranges` | **字・顔・商標を確かめた区間**（秒）と、確かめた回とやり方 | `[{"from":3.0,"to":9.5,"ep":19,"how":"1秒1コマ＋疑いは原寸","faces":0,"text":0}]` |
| `ng_ranges` | 使えない区間と理由 | `[{"from":12,"to":15,"why":"屋上の看板の字"}]` |
| `used_in` | 使った回・カット・区間・役（本体・頭・尻） | `[{"ep":19,"cid":"cc14","from":3.0,"to":6.2,"role":"head1"}]` |
| `claims` | 申し立て（日付・中身） | 1件でもあれば以後使わない |
| `credit` | 画面の出典の行 | 「イメージ（フリー素材）：Pexels／作者名」 |

## 5. 回をまたいで使う決まり
1. 素材を探す前に棚を引く（`what` と `place` で）。棚に合う物があれば、新しく探すより先にそれを使う
2. **字と顔は区間ごと**：使う区間が `ok_ranges` の中なら焼き直しの確かめは要らない。外なら、その区間を 1秒1コマで焼いて字・顔・商標を探し、`ok_ranges`（または `ng_ranges`）に足す（素材の「候補」は在庫ではない）
3. **時代と型は回ごとに判断**（`era_note` は参考）。同じ海の映像でも、回の時代・場所に合わなければ使わない
4. 「イメージ」の札と出典の行は毎回出す（credits.json にも）。20%の数・【映像あり】には数えない（§2-5c）
5. 同じ回で同じ区間を2回使わない（門番＝回の映像の一覧の「同じ素材の2回」）。続けて見る人の既視感を避けるため、**直近3本で使った区間は別の区間か別の素材**を先に考える（`used_in` で引く）
6. 申し立てが来たら `claims` に書き、以後どの回でも使わない。公開ずみの回は直さない（記憶 `feedback-published-videos-are-not-revised`）
7. 許諾の頁は取得のたびに読み直す（`license_checked` を更新）。許諾の名が変わっていたら止めて相談
8. **棚に書くのは本線に push するチャットだけ（1度に1本）**。並行のチャットは自分の回の `clips.json` にだけ書き、棚への反映は push するチャットでまとめる（書く場所が重ならないように）

## 6. 回の側（`ref/epNN/clips.json`）との関係
- 回の `clips.json` の行＝今までどおり（`url`・`media`・`"stock": true`・`md5`・`w`・`h`・`sec`・`license`・`author`・`site`・`credit`）＋ **`"stock_id": "<鍵>"`**。道具（`footage.fetch`・`check_text_screens.is_stock`）は回の `clips.json` だけを読む＝**道具を直さずに使える**
- 棚と回の食い違いを見る門番（⑤b-1 で書く・案）：回の `"stock": true` の行がすべて棚にある／使う区間が `ok_ranges` の中／`claims` のある鍵を使っていない／`media`・`md5` が棚と同じ。置き場は ⑤b-1 で決める（`tools/` に置くならそのチャットで）
