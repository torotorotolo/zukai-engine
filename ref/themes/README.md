# 題材の帳簿 — ①題材のチャットは、まずここから始める

**2026-09-08 カズヤくん指示。「毎回1から調査をするのはトークンの無駄」。**

これまで①題材のチャットは、ジャンル走査・広域の当たり率・素材の実測を毎回1からやり直していた。
6本目の実行で **YouTube API 約5,830／10,000単位**と、チャット1回ぶんのやり取りを丸ごと使っている。
しかも結果は `analytics/` に置かれ、そこは **`.gitignore` で git 管理外**なので、
次のチャットからは「無かったこと」になっていた。

→ **競合の公開データと素材の実測値だけを、ここ（git 管理下）に貯める。**

⚠️ **`analytics/` を git に載せてはいけない**（このchの内部数字＝再生・維持・CTR が入る）。
ここにあるのは他局の公開データと、Commons/NARA の点数だけ。自分のchの動画は1本も入っていない。

## 次の①題材チャットの手順（この順でやる）

### 0. まず帳簿を読む（API を1単位も使わない）
```bash
python tools/theme_ledger.py table              # 全部
python tools/theme_ledger.py table --only-open  # まだ採否が付いていない題材だけ
```
**保留（△）の題材には、次に何を確かめれば決まるかが `note` に書いてある。**
2026-09-26 時点の保留は **18件**（16・17本目①＝ヴァイオント・ダム災害・中華航空140便 を採用。ヴァイオントは09-23・09-24 の再審から漏れていた素材だけの却下を戻したもの・140便は帳簿に無かった題材を母集団から掘ったもの）。
16・17本目①の候補の残り＝**大韓航空007便（17本目の次点）・東海村JCO・Therac-25**（`note` に次に確かめること・`legend_2026-09-24` に芯の確認）。
09-26 に保留へ入れた＝**PEPCON**（2局とも1.0×超・死者2名で骨が未確認）・**板橋ダム**（4本4局・死者数が割れる）・**大邱地下鉄**（2本2局・14本目と型が重なる）。
🔴 **ここで決まるなら、走査も広域も回さなくてよい。**

🔴 **①の最初に `python tools/theme_ledger.py audit` を回す（2026-09-26）。** 近所比の数字（×）がどこにも無い却下＝**再審の漏れの候補**を全部出す。
09-24 は「reason が『素材』で始まる却下」を拾ったが、書き出しの違う素材だけの却下（『全画面74点は…』『🔴母集団の…』）を取りこぼし、
**ヴァイオント・ダム（6本6局・1.97×）が2回の再審から漏れていた**。書き出しでなく中身で拾う。出た行は人が読んで、需要・型の却下か素材だけの却下かを決め、`recheck_<日付>` に数字を書く。
🔴 **再審のメモも数え直す**＝09-23 の再審は板橋ダムを『1局だけ』（実際は4本4局）、大邱を『0.53×で割れる』（0.53× は別の事故＝1995年の上仁洞ガス爆発）と書いていた。

⚠️ **`shelf_n` / `shelf_ch` は書いた日の値で、勝手には更新されない。**
2026-09-16 のディープウォーターは `shelf_n:0`（母集団に1本も無い＝需要が測れない）と書かれていたが、
実際には pattern が2本に当たっていた。**保留を読むときは棚の数を自分で数え直す**
（pool.json を直接引く）。→ 記憶 `feedback-absence-of-a-word-is-not-absence`

### 1. 母集団を更新する（約430単位）
帳簿の保留を全部つぶしても決まらないとき、または前回から3か月以上あいたときだけ。
```bash
python tools/yt_genre_scan.py channels --min-subs 3000 --max-channels 16
python tools/yt_genre_scan.py scan --themes analytics/themes/ep5_keywords.json \
       --out ep7_genre --dump ep7_pool
python tools/theme_ledger.py merge --pool analytics/themes/ep7_pool.json
```
- `channels` は**手で足した局を温存する**（`[温存] …` と印字される）。
- `merge` は同じ動画IDなら**新しいほう**を採る（再生数が育っているため）。

### 2. 母集団を掘って、新しい候補を探す
🔴 **候補の名前を自分で思いつくところから始めない。** それをやると
「思いつかなかった題材」は構造上ずっと見えないままになる。
```bash
python tools/theme_ledger.py neighbor --ledger      # 帳簿の全題材を測り直す
python tools/theme_ledger.py neighbor --words キーワード
```
`pool.json` を直接読んで、再生数の上位や公開月ごとの中央値を見るのが早い。

⚠️ **語の網は必ず取りこぼす。** 6本目の実行では
チャレンジャー号（3本→実は204,490）・ウィンズケール（0本→実は219,106）・
マルパッセダム（0本→実は125,081）を取りこぼしていた。**題に事故名が入っていない動画がある。**
逆に、ステーションNC火災の230,447は**別の火災**（1977ビバリーヒルズ）だった。**中身を見る。**

🔴 **題名の文字の形でも取りこぼす（2026-09-24・14/15本目①で発見）。**
`pool.json` の題名の **17%（311/1,815本）は濁点を別の文字で持つ形（NFD）**で、揃えずに照合すると
**濁点を含む語（チェルノブイリ・コンコルド など）ではその311本が見えない**。
`theme_ledger.py` は 09-24 から NFKC に揃えて照合する。**自分で pool.json を直接引くときも
`unicodedata.normalize("NFKC", title)` を題名と語の両方に掛ける**（陽性対照＝`neighbor --words チェルノブイリ` が LOt7Kvjpr14 に当たる）。
題名に名前が出るだけの**別の事故**は帳簿の `exclude`（または `--exclude`）で外す
（セウォル号の網は『東方之星』『西海フェリー』『ナムヨン号』『加湿器殺菌剤』の回を拾っていた＝帳簿の「12本8局・運命のフライト7.54×」は誤りで、実際は8本8局）。

🔴 **外国の名前は表記ゆれでも外れる（2026-09-26・16/17本目①で発見）。** NFKC は濁点の形は揃えるが、
**「ヴァ」と「バ」のような書き分けは揃えない**。ヴァイオント・ダムは帳簿の網が『バイオント』だけで、
運命のフライトの『ヴァイオント』（38分 4.70×）と、**題名に名前の無い本命局の回**（『世界一の巨大ダムが人災で崩落』32分 2.53×）を取りこぼし、
「3本3局・近所比なし」のまま素材で却下されていた（実際は6本6局・中央1.97×）。
→ **外国の地名・人名は「ヴァ/バ・ヴィ/ビ・ヴェ/ベ・長音の有無」を網に入れる。採る題材は中身の語（『巨大ダム』）と数（『2000名』）でも引き直す**
（マルパッセも本命局の題は『フランスの先進的アーチ式ダムが崩落』で名前が無かった）。

### 3. 需要は「近所比」で足切りする
近所比 ＝ その動画の再生数 ÷ **同じ局が前後45日に出した動画の再生数の中央値**。
素の再生数は「局の大きさ」と「経過日数」を写すので比べられない。

- ⚠️ **本数が少ないと暴れる**（小さい局の1本が7〜99倍を出す）。**順位付けに使わない。**
- ⚠️ **1.0×を割ったら落とす**、という足切りだけに使う。
- ⚠️ 帳簿の `neighbor` は **2026-09-23 から中央値**（全部の値は `neighbor_all`・動画IDは `hits`）。
  それより前に書いた項目は、中央値（TWA800）と最大値（グレンフェル）が混ざっている。
- 🔴 **熟成の線（公開30日未満を外す）は「母集団を測った日」から引く（2026-09-26 に道具を直した）。**
  `pool.json` の再生数は測った日（09-08）の値なのに、道具は線を**今日**から引いていた＝日が経つほど、測った時点で
  公開12〜30日だった回が「熟成済み」として分子にも分母にも入る（陽性対照＝ソユーズ1号の回は旧の道具で 0.95×・直した道具では比較不可）。
  基準日は既定で「いちばん新しい公開日の翌日」・`--asof` で上書きできる。16/17本目①では保留15件の判定は動かなかった（ゴイアニア 3.27→3.18 だけ）。
  直したあと帳簿の全件を道具と突き合わせると12件の値がずれたが、**判定に効くものは0件**＝熟成の線の小さなずれ（テネリフェ・ゴイアニア・ソユーズ11号・トルコ航空981便ほか）と、
  09-23 より前に「中央値でなく1本の値」を書いた項目（キャッスル・ブラボー 2.43→中央1.56・香港 4.07→1.63 など）。保留の2件だけ値を直した（`neighbor_prev` に旧値）
- 広域の当たり率（`yt_theme_probe`）は窓が**6か月以上前で終わる**ので、
  **直近に伸びた題材を構造上見られない**（キー橋がこれで n=3 になった）。近所比で補う。
- 広域を回すなら、**基準として3本目スレッシャーと5本目SL-1を必ず同じ実行に混ぜる**
  （2026-09-08 の実行では09-07の値と小数点まで一致した＝道具は安定している）。

### 4. 素材を実測する（🔴 ここでいちばん多く落ちる）
```bash
python tools/commons_probe.py cat "Category:…" --depth 2
python tools/nara_probe.py search "…"
```
- **カテゴリ名は当てずっぽうで打たない。** 無いと 0点 と出て「素材が無い」と誤読する
  （TWA800 は `Category:TWA Flight 800` が0点、正解は `…(1996)` で84点）。
- ⚠️ 保存された JSON は `summary` が分類ずみ、`rows` が**生のライセンス名**。混ぜて数えない
  （`Public domain` を `PD` で照合して 0点 と誤って出した）。
- 🔴 **動画（動く素材）を写真とは別の軸で数える。**
  試写でカズヤくん「実際の映像は引き込まれる」。**本レンダは1920×1080なので、
  それ未満の動画は保険にしかならない**（SL-1のブリーフィング映画640×480＝保険扱い）。
- `rows` の `mime` が `video/webm` などのものを数えるのが早い。
- 🔴 **2026-09-23 から素材の方針が変わった（全回に恒久）**＝写真・映像は全カットの20%以上（上限なし・門番は警告だけ）、
  PD以外（Googleアースの映像・写真／事故の報道写真の引用）も使う。**①で PD・CC の点数だけで題材を落とさない。**
  見るのは「その事故の写真がそもそも存在するか」「一次資料（報告書・判決文）が取れるか」「記録映像（【映像あり】）」。
- ⚠️ `nara_probe.py` は結果を **`analytics/materials/` に自動で保存する**（並行作業中の「リポに書かない」約束に触れる）。
- ⚠️ カテゴリを「点数の多さ」で自動に選ぶと**追悼・慰霊のカテゴリ**を拾う（13本目①のグレンフェル）＝カテゴリ名は人が読んで選ぶ。
- ⚠️ 語の網は**題名に事故名が無い回**を取りこぼす（コンコルドの回に『エールフランス航空4590便』だけの題が1本あった）。
  採る題材は、便名・場所・部品の語でも引き直して**型の外**を読む（トルコ航空981便は『981便・貨物ドア・DC-10』で引き直した）。

### 5. 決まったら帳簿に書き戻す
`ledger.json` の該当題材に `verdict`・`neighbor`・`material`・`reason`・`measured` を書く。
**落とした題材も必ず理由つきで残す**（同じ題材を二度調べないため）。
`updated` と `runs` も更新する。

## 構造の教訓（`ledger.json` の `structure` にも入っている）

- **実質の分かれ目は「米連邦か否か」。** 米連邦機関（NIST/NBS・DOE/AEC・海軍・NTSB・CSB・NASA・
  USACE・USCG）が調査した事故は、報告書ごと写真も実験映像もPD。
  日本・韓国の1990年代以前は事故当日の写真がほぼ例外なく報道機関のRM。欧州も自由な原本が薄い。
- **NARA の `Restricted - Possibly（Copyright）` で題材を落とさない。**
  シリーズ一括の定型文のことがある（SL-1は兄弟299/299で一括＝PDだった）。
- 🔴 **記録映像を使った回は `【映像あり】` をタイトルの先頭に置く**
  （2026-09-08 カズヤくんが4本目に追加・5本目を先頭へ移動）。
- 🔴 尺は**下限27分・上限40分**。**目標は36〜37分**。
  2026-09-21 に母集団1,815本を測り直した結果、**有意に勝つのは 35〜40分だけ**
  （近所比の中央 1.33・1.0超が66%。並べ替え検定 p=0.0071 対 25-30分／p=0.0235 対 30-35分）。
  ⚠️ **30〜35分は 25〜30分と区別がつかない**（p=0.2695）＝下限まで下げるのと同じで何も買っていない。
  ⚠️ 旧記述「上限38分・勝ち帯35〜50分（1.47倍）」は粗い。40〜50分は 1.13 で 35〜40分に届かない。
  道具＝`ref/ep11/dur_probe.py`／`dur_test.py`。→ 記憶 `feedback-duration-band-only-35-40-wins`
