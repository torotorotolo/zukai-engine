# 🔴🔴 共通の道具のバグ — `tools/commons_probe.py` が大判 TIFF を捨てている

**見つけた日**: 2026-09-12（7本目 9.11 の①題材・素材レーンの検算係）
**効く範囲**: この回だけでなく **過去の回・他の題材の素材の見積もり全部**

---

## どこ

`tools/commons_probe.py` 185〜192行付近、全画面に耐える点数を数える判定：

```python
if bd is not None and bd < MIN_BITDEPTH:
    # 落とす（＝1ビット2値スキャンとみなす）
```

## 何が起きているか

Commons の API は **TIFF / WebP について bitdepth を報告せず 0 を返す**。
この道具はその 0 を「1ビット（2値）スキャン＝全画面に使えない」と読んで捨てている。
実際には 0 の多くは**無圧縮 RGB の大判 TIFF**（実測 3.0〜6.0 バイト/画素）。

## 実測（9.11 のプールで）

| | 道具の値 | 実測 |
|---|---|---|
| bitdepth=0 の点数 | 343点を「1ビット」として除外 | **真の1ビットは2点だけ** |
| その343点の幅の中央値 | — | **4,082px**（プールで最も大きい絵） |
| 全画面に耐える写真 | 7,546点 | **7,880点** |
| 当日（2001-09-11）の写真 | 83点 | **529点** |
| `Category:Library of Congress images of the September 11 attacks` | 251点あるが全画面**1点** | **251点すべて幅≥1280・250点が4,000px級TIFF** |
| 事故の前の米連邦§105 | 5点 | **35点** |
| PD系の米連邦§105 | 2,203点 | **約2,804点** |

## 直し方（提案）

1. bitdepth が 0 / None のとき**捨てない**。別の手がかりで連続階調かを決める。
   手がかり＝ mime（`image/tiff`・`image/webp`）／**ファイルサイズ ÷ 画素数（バイト/画素）**。
   ⚠️ **真の1ビット2値スキャンは落とす**という元の目的は保つ（網は緩めない）。
2. 🔴 **陽性対照と陰性対照を両方置く。**
   - 陽性＝真の1ビット2値スキャンが実際に落ちること（**件数でも値でも**動く）
   - 陰性＝大判 TIFF が落ちないこと
   ⚠️ 件数だけの対照は、もともと全件該当の指標では動かない（→ `feedback-verify-your-own-instrument`）
3. 🔴 **過去の回・保留題材の見積もりを取り直す。** TIFF が多い題材
   （Library of Congress・HABS・NARA 由来）ほど被害が大きい。
   `ref/themes/ledger.json` の保留＝TWA800・コロンビア号・テネリフェ・ラジウムガールズ・ゴイアニア。
   **採否が変わるものがあれば理由つきで書き戻す。**

## ついでに見つかった小さいバグ（この回の使い捨ての道具）

`analytics/materials/ep7/vid_probe.py` の `cat_files` が `if d+1 < depth:` と書いてあるため、
**`--depth N` で実際に降りるのは N−1 段**。正しくは `if d < depth:`。
これが原因で陽性対照のキー橋が「動画29本」と出て、**既知の値と一致したことでバグが隠れた**
（真の値は30本・5,494.4秒。落ちていたのは President Biden Delivers Remarks… の1920px・1,080.9秒）。
⚠️ **既知の値そのものが同じバグで作られていた可能性を疑う**、という型の事故。
