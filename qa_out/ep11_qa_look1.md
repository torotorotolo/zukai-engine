## 3. 🔴🔴 1回目の焼きで見つけた穴 ── **動く映像7欄が黙って静止画に落ちていた**

### 3-1. 何が起きていたか

1回目の Actions（[run 35672528744](https://github.com/torotorotolo/zukai-engine/actions/runs/35672528744)・sha `788600a`）は
**全22段が success**でした。が、ログを読むと：

```
✓ 切り出し完了 0/7 カット: なし
⚠️ 7 カットは**静止画に落ちる**。パイプラインは止めない。
　 ⚠️ pr02 / pr07 / c101 / c307 / c413 / c503 / c603
　 　「動画のコマが無いので**静止画に落ちた**」
```

**7欄すべてが落ちていました。**段が緑なのは `continue-on-error: true` のため
（＝記憶 `feedback-pipes-mask-exit-codes` の「Actions の continue-on-error も失敗を緑に見せる」）。
🔴 **`fetch --check` は ✓ を出していました**＝あの門番は**書いた秒しか見ておらず、URL を1度も引いていなかった**。

### 3-2. 真因① ── `clips.json` の `url` が **archive.org の引用の頁**だった

```
ffmpeg -i https://archive.org/details/ChallengerAccidentandInvestigation
  → Error opening input files: Invalid data found when processing input
```

`/details/` は**人が見る頁（HTML）**で、ffmpeg は読めません。
⑤c は帯を `ref/ep11/grab_clips.py` で**手元に抜いてから**進めたので気づけませんでした
（`grab_clips.py` のほうは `/download/…` の直リンクを持っていて、実際に抜けています）。

🔴🔴 **`modal_app.py` も `python3 tools/footage.py` を呼びます**（262行・304行、`check=False`）。
＝ **直さなければ⑥の本編mp4にも、7カットが静止画のまま載っていました。**

### 3-3. 真因② ── SAR 8:9 の直しが **一度も当たっていなかった**

`_cut_stream` が SAR の直し（`scale=iw*sar:ih,setsar=1`）を当てる条件は **`dispw != w`** で、
読む鍵は **`dispw`**。ところが `ref/ep11/make_clips.py` は**`square_w`** にしか書いておらず
（`square_w` は `grep` した限り**誰も読んでいません**）、条件が `720 != 720` で常に偽でした。

| | 実測 |
|---|---|
| 本番の経路で抜いたコマ（直す前） | **720×480 の正方画素** ＝ **横に 12.5% 太い** |
| 正しい寸法 | **640×480**（720 × 8/9） |
| 門番 | **1本も鳴らない** |

`make_clips.py` の冒頭には「切り出し側が `scale=iw*sar:ih` を当てられるようにする」と
書いてありました。**書いてあるのに、当たっていませんでした。**
→ 記憶 `feedback-container-labels-lie-about-the-picture` ／ `feedback-settings-may-not-reach-the-picture`

### 10-1. 🔴🔴 いちばん大きい発見 ── **`compare` の6カット全部が「大きな空き長方形」を立てていた**

⑤c-1 のシートは「**量が大きな空き長方形だけで表されている**」と6か所で書いていました。
原寸で見て、**真因は `titan_fig.compare()` の `ref=` の使い方**だと分かりました。

`ref` は docstring に「**外の基準**（タイタニックの深さ 3,840m）を薄い枠で満杯の棒として置き、
そこにその名前を書く」と書いてある引数です。ところが11本目は**6カット全部**で、
量ではないもの（単位の注・出どころ）を `ref` に渡しています。

| カット | `ref` に渡した文字 | それが量かどうか |
|---|---|---|
| `pr08` | 摂氏。華氏では 36 と 51 | ✗ 単位の注 |
| `c513` | 点火から0.6秒で開ききる | ✗ **時間**（棒は mm） |
| `c518` | 摂氏で測った値 | ✗ 単位の注 |
| `c520` | 組み立てたときの実測（平均） | ✗ 出どころ |
| `c609` | 摂氏 | ✗ 単位 |
| `c702` | 実測 | ✗ 出どころ |

絵はこうなります（原寸で確認）：**項目ごとに、枠の高さいっぱいの破線の長方形が立ち、
その中に本物の棒が沈んでいる。**左の1本にだけ上端に文字が入り、**右の1本は文字すら無い＝ただの空き箱**。
`pr08` は 2.2℃ の棒が **52px**、破線枠が **324px** なので、**画面の面積では空き箱が主役**です。

🔴🔴 **副作用がもう1つ。**`compare` の「値の差が5%未満なら棒をやめろ」という門番は
```python
if bar and not ref:      # ← ref があると一度も回らない
```
＝ **`ref` を渡した6カットでは、差が1%でも鳴りません。** `c518`（差 9.1%）が素通りした理由です。

**直し方（⑤c' で決める）**
1. `ref` を**外す**（単位は `unit` と `note` が既に持っている）。→ 空き箱が消える。**いちばん安い**
2. 単位の注は `note` へ移す（`pr08` の「華氏では 36 と 51」は note に足す）
3. `ref` を外すと5%の門番が生き返るので、**`c518` は棒をやめて数字に語らせる**（下の 10-3）

**検品画像が「終わりかけ」の1枚**で、`c405` は最後の段の出る秒が偶然どちらも 7.46s だから。
直した粗は「**矢印3本が 0.35〜4.05秒のあいだ、節が1つも無いまま宙に浮く**」という**動きの粗**で、

🔴🔴 **教訓＝画素の差分は「時間割の直し」を確かめられない。段の数と出る秒を本番の関数で測る。**
